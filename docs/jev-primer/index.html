What shipped¶

  • Jev is the first “System One” model from TypeSafe AI, founded by Diogo Almeida — co-author of the InstructGPT paper (the work that turned GPT-3 into ChatGPT). Announced on X after ~2 years of development; early access, waitlisted.
  • It is not a generative model. It emits no text, code, or explanation. You send it a piece of unstructured state (an email, a log line, a JSON blob, a support ticket) plus a set of typed questions, and it returns typed decisions with calibrated probabilities.
  • TypeSafe’s own framing: “a function call with frontier intelligence” — unstructured state in, typed probabilistic decision out. Third parties describe it as “an AI-powered if statement.”
  • “System One” is Kahneman’s name for fast, intuitive cognition — as opposed to System Two, the slow deliberative reasoning that chatbots and reasoning models imitate. The product claim is a new class of model, not a smaller LLM.

The output surface — three primitives, nothing else¶

Primitive What it returns Example
Choice One option from a list you supply (≤255 options), probability per option, plus confidence billing / technical / sales
Score Position on an ordered rubric, probability per level, plus confidence churn risk 0–1
Noul A single yes/no claim → calibrated probability that it’s true “does this message express urgency?”

Key structural property: all three compose in one API call, evaluated in parallel against one shared read of the state — up to 255 questions per call. TypeSafe’s docs say adding questions “barely changes the response time.” One state ingestion → a whole questionnaire of judgments. That is the thing a token-at-a-time generative model cannot do.

RLCD¶

RLCD = Reinforcement Learning for Calibrated Decisions (TypeSafe’s term). The training target is calibration, not correctness or preference:

  • RLHF optimizes for human-preferred output.
  • RLVR optimizes for verifiable correctness (test passes).
  • RLCD optimizes for calibration: a model that says it’s 70% confident should be right ~70% of the time. Every answer therefore ships with an honest probability distribution — the designed failure mode is “a model that knows when it doesn’t know,” so your code decides what to do about it.

Note: the acronym collides with an older 2023 paper — “RLCD: Reinforcement Learning from Contrastive Distillation” (ICLR 2024) — an alignment method unrelated to TypeSafe’s. TypeSafe’s is for calibrated decisions; the paper’s is from contrastive distillation.

The intended usage pattern is three confidence bands: high-confidence answers auto-execute, mid-confidence gets flagged/confirmed, low-confidence routes to a human. Thresholds live in your code, not the model. TypeSafe explicitly tells you to validate calibration on your own labeled data — confidence thresholds are use-case-specific.

Numbers, sorted by who produced them¶

Vendor claims (TypeSafe): - $0.042 per million input tokens (~$42 per billion); output tokens free (“too cheap to meter”). - 70–500 ms latency; up to 20–200× faster and 40–400× cheaper than comparable LLMs on System One-type tasks (internal workflow evals — upper bounds 193.6× speed, 444.6× cost; benchmarks use frontier-model predictions as reference answers, not verified ground truth).

Only independent test published so far (Every, head of evals Mike Taylor): - 37 documents × 21 questions = 777 judgments in <0.7 seconds for ~a quarter of a cent (~$0.000003 per judgment; ~300k+ judgments per dollar). - vs Claude Fable 5.1 on writing-defect checks: 0.35s vs 8.83s median per passage — ~25× faster at ~1/580th the cost. Jev caught 6/7 planted defects; Fable caught 7/7. - Verdict: “good but not perfect” — speed and cost claims survive third-party contact; accuracy sits a notch below frontier; sample too small for production conclusions.

The architecture it’s designed for: two models, not one¶

Jev is the fast control loop; a generative model is the content factory. Documented pattern:

  1. Jev decides — typed judgment over state (route this, score that, is this risky?).
  2. Generative model executes — writes the reply, code, explanation.
  3. Jev verifies — is_this_on_policy?, does_this_answer_the_question?, is_this_tool_call_safe?

TypeSafe’s documented use cases: RAG relevance scoring/context selection, agent guardrails (tool-call checking, prompt-injection detection, risky-action flagging), coding-agent output review, model routing, feature extraction. Jev is early-access only; OrcaRouter et al. do not serve it.

What “Jev-like” means as a class¶

For the economic analysis in these files, “Jev-like” / “decision model” / “System One model” means: a model that maps unstructured state to typed probabilistic judgments at near-zero marginal cost, sub-second latency, with an honest confidence signal. Jev is the first commercial instance (API-only, proprietary). Nothing in the class definition requires TypeSafe — expect open and on-device versions; a ~1B-parameter decision model running locally is the obvious endpoint and changes the economics further (zero marginal cost, offline, private).

Honest limits (from the previous session, still true)¶

  • It’s judgment, not creation. It picks and scores among options you give it; it cannot author the options. Novelty still needs a generative slow lane.
  • Calibration ≠ correctness. A well-calibrated model is still wrong 30% of the time at 70% confidence. The bands make failure manageable, not absent.
  • Vendor claims are 48 hours old and unaudited. Architecture unpublished, weights unreleased, benchmarks internal, one external test. Treat the 200×/400× numbers as marketing until replicated.
  • Distribution shift is the real enemy. Calibration is trained against a data distribution; adversarial inputs (fraud, moderation evasion) and domain drift degrade it silently. TypeSafe’s own docs say: test on your data.
  • Accountability isn’t delegated. Regulated decisions (credit denial, medical triage, benefits) legally need reasons and a liable party; a Noul gives a probability, not an adverse-action reason code. Decision models slot into these workflows but don’t remove the compliance layer.
